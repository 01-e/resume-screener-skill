# resume-screener · 单岗位简历初筛

**一次一个岗位、一个本地目录。** 只处理顶层可选中文字的 PDF / DOCX；不抓平台、不查重、不做 OCR。扫描件、加密件、旧 DOC 和损坏文件会单列给 HR，不会因为机器读不了就判为不匹配。

## HR 怎么用

挂载后可以这样开场：

> 用简历筛选 skill 帮我筛数据分析师。JD 是……；简历都在 `D:\招聘\分析师\收件`。先给我核对门槛。

1. 看《初筛门槛确认表》，把 JD 没写清楚的业务要求补上。例如“会写 SQL”是必须，还是做过续费分析优先？确认最终版本后才开始读简历。
2. 收到可单独转发给授权业务经理的离线 `简历筛选报告.html`、用于统计留档的 `简历筛选汇总表.xlsx` 和 `01_推荐`、`02_待定`、`03_不匹配`、`04_异常需人工查看` 四个目录（或包含它们的 ZIP）。推荐/待定按分数从高到低排，同分按原文件名排；极简不匹配显示“未评分”，列在数值分后；可按分档筛选。每项判断可通过原文件名与评估项编号在“逐项证据”页追溯，异常页有原文件名和处理建议。
3. 先看推荐，再扫待定与异常。缺证不是不符，机器初筛不代替 HR 决策。请勿直接打开来历不明的异常附件。原件始终留在收件目录，归档是副本。

## 管理员一次性挂载

- 需要支持原生文件型 Skill 的办公 Agent，以及宿主**本地** Python 3.10+、读收件目录和写私有工作/交付目录的权限。没有独立服务、数据库或外部解析/模型 API，不需 API Key；语义评估使用已部署在本地的宿主模型。
- 把整个 `resume-screener/` 放到宿主配置的技能目录中，或通过支持本地 Skill 的入口导入，保留 `SKILL.md`、`scripts/`、`references/`、`assets/` 的相对位置。刷新技能或新开会话，按名称触发。目标宿主如 WorkBuddy 需**实测**本地脚本权限；不要只粘贴 `SKILL.md`，也不要假定所有版本都能读桌面目录。
- 在**实际执行脚本的 Python 环境**中，从本技能目录一次安装依赖：`python -m pip install -r requirements.txt`。离线部署可由管理员准备对应平台的 wheel，然后执行 `python -m pip install --no-index --find-links "本地wheel目录" -r requirements.txt`。运行期不下载组件、不上传简历。HR 不需要自己敲命令。
- 私有工作区放在仅授权 HR 可读的位置。给技能一个**新的**批次路径和新的交付名，两者、收件目录三者不要相互包含。只支持宿主可见的文件路径；不可见时先在授权范围内共享/导入文件，不要用聊天粘贴原文来绕过权限。

## 数据经过哪里

本地脚本把抽取的原文写到 `texts/`；本地模型每次读取一个按原文件名隔离的 3–5 人微批，提取真实姓名、联系方式和评估证据。`manifest.json` 包含原件路径信息、校验值及异常原因。导出脚本核对每组 `evals/batch_NN.jsonl` 后写 HTML、Excel 并复制原件，不修改输入目录。报告无需服务器或网络，双击即可查看。

原文、评估、报告和归档都可能包含真实个人信息，只交给有权限的接收人。ZIP 未加密。成功或放弃批次后，按组织政策清理私有工作区，不将工作区打包分享。升级至 V1.2 请从确认口径新建批次，不复用旧批次的评估文件。

## 出错时怎么办

- **缺少组件/无法运行 Python**：由管理员核对沙箱内解释器及依赖；不改用第三方在线解析。
- **目录里没有可筛文本**：确保文件在顶层。全异常的非空目录仍会生成报告、Excel 异常页和原件副本；空目录或无读取权限则先修正输入。
- **提示证据不属于该人 / 缺份**：按 `manifest.json` 的批次和原文件名修正相应评估，不填虚构证据凑数。原件或标准已变则重新确认、另开批次。
- **目标目录不可写**：若可读取原件，导出器会在 `--fallback-dir`（缺省为批次的父目录）尝试生成完整 ZIP；也可主动指定 `--zip`。已存在的交付不会被覆盖。若连工作区都不可写，需先提供可写位置。

## 验收边界

维护者可从项目根运行 `python -X utf8 -m unittest discover -s tests -v`，用合成文件验证原文解析、证据校验、HTML、Excel、四档归档与 ZIP。**本地冒烟通过不等于产品指标达成**：上线前请在实际 WorkBuddy 环境测 50 份从 HR 确认到交付的用时（目标 ≤2 分钟），分别记录是否并行与是否降级 ZIP；再用 1–2 份 JD、30 份有业务反馈的授权历史简历盲测，逐条回查原文。推荐一次采纳率目标 ≥80%，优质简历误杀率 ≤1%，事实幻觉率 0%；30 份只是前置排雷，不足以证实 1% 红线。不满足护栏应暂停推广，修正口径后重测。

## 报告模板

`assets/report_template.html` 是「cl_design」原始模板。导出时只替换 `const REPORT_DATA = ...;` 的 JSON 对象，不注入字体或样式，不改写 HTML 或交互脚本。原模板含 Google Fonts 外链：浏览器会尝试加载字体，断网时使用本地回退字体，报告内容和交互仍可用。模板及安装包保留原模板自带的数据；交付业务方时请使用导出的 `简历筛选报告.html`，而非模板文件。

## 定位耗时

命令末尾的 `[TIMING] parse` / `[TIMING] export` 计本地处理秒数（不含解释器启动）；子项单列抽取、打包、评估校验、Excel 和 HTML。解析自动选择进程数：Windows 下不超过 32 个文件且总大小不超过 1 MiB 时使用单进程，避开小批启动开销；其他批次保留并行（最多 4 个进程）。可用 `--workers 1` 至 `--workers 16` 显式覆盖。模型阶段请在实际宿主另记首批开始到最后一份 JSONL 写完的墙钟时间、正文读取次数、输入/输出 Token；并发任务时不要把各任务的耗时相加当作端到端耗时。截断补页属于额外读取，不能为追求耗时跳过。
