# V1.2 数据契约（UTF-8 JSON）

以下是合成示例，不是通用岗位标准。输入字段精确匹配，不加注释、额外字段或重复键。所有评估都依据同一批已确认的口径。

## `criteria.json`：确认后每批一份

```json
{
  "role": "续费分析师",
  "confirmed": true,
  "hard_gates": [{"id": "H1", "text": "实际用 SQL 完成业务分析；只列工具名不算证据"}],
  "hidden_requirements": ["HR 补充：优先做过续费改进验证的人，计入 D2，不作硬门槛"],
  "dimensions": [
    {"id": "D1", "text": "独立编写业务分析查询", "weight": 60},
    {"id": "D2", "text": "验证续费改进效果", "weight": 40}
  ],
  "recommend_min": 75
}
```

`confirmed` 仅在 HR 明确同意本版本后设为 `true`。`hard_gates` 为全部确认的必需项，可空；`hidden_requirements` 单列 HR 补充内容，没有则 `[]`。确认时将补充中的必需要求纳入 H 项，将偏好落实在 D 项及其权重，不重复计分、不把偏好当否决条件。门槛和维度各有唯一 H/D 正整数编号；维度非空、正整数权重之和为 100。推荐线是 1–100 的整数。

## 批次输入与结果分片

`manifest.json` 绑定同批口径、原文件名、原件与解析文本校验值、异常原因，以及 `microbatches[].key/filenames`。只读当前 `batches/batch_NN.md`。`> ` 是数据行前缀，不是原文的一部分。每人预览上限 4000 个正文字符。截断时以同组 `batch_NN.more.md` 补齐中段；批头中带补页末尾的 `review_token`，导出时核验。原文始终保留在 `texts/`，用于证据核对。不能把辅助字段或别人的片段当引句。

每批只写一个 `evals/batch_NN.jsonl`（UTF-8，不加代码围栏、缩进或说明）。第一行 `{"batch_id":"清单中的批号","batch":"batch_01"}`；仅有补页时增加 `"review_token":"读完补页所得值"`。之后每人一行；不重复批号或口径。输出文件必须与计划一一对应，导出拒绝缺人、重人、串组或不属于本人的证据。

### 推荐 / 待定：完整数据，紧凑写法

```json
{"filename":"林青.docx","tier":"待定","name":"林青","phone":"138-0000-0001","email":"lin@example.org","wechat":null,"years":3,"years_quote":"共 3 年工作经验","education":"统计学本科","latest_role":"数据分析师","gates":[["H1","满足","独立用 SQL 分析续费订单"]],"dimensions":[["D1",4,"定位到两个流失环节","自己查订单找到了流失环节。"],["D2",null,null,"简历未提及改进后的结果。"]],"summary":["能自己查出续费流失环节；改了有没有用，简历未提及。",["D1","D2"]],"highlights":[["有查订单定位流失的实例。",["H1","D1"]]],"risks":[],"gaps":[["简历未提及改进后的验证结果。",["D2"]]]}
```

- 所有显示字段均保留；姓名、手机、邮箱、微信、学历和最近职位是本人原文连续片段，不从文件名猜、也不计分。总工作年限只取原文明示数字并提供 `years_quote`；不明确时两者 `null`。
- `gates` 每项 `[编号,满足/不符/不明,引句或null]`；`dimensions` 每项 `[编号,等级或null,引句或null,一句说明]`，与锁定项一一对应。等级 0=有明确反证，1=接触，2=做过部分，3=独立完成，4=有达到或超出要求的成果；缺证是 null 而非等级 0，说明须写“简历未提及”。每条引句（含年限）最长 **30 个字符**，须是本人连续原文，不拼接，不删掉否定或主体。总分由脚本计算 `Σ(权重 × 等级 / 4)`；缺证不贡献已证实分，不重分摊权重。
- `summary` 是 `[人话评语,[证据编号,...]]`；亮点、风险、缺口为同形条目数组，没有填 `[]`。不重复凑句，每项可用一句话。每个判断至少一个属于本人的 H/D 引用；引用空证据要明写“简历未提及”。机器能查引句存在，不代替语义核验。

### 不匹配：五字段，不走逐维评分

```json
{"filename":"王五.docx","name":"王五","tier":"不匹配","score":null,"reason":"OFF：本人明确「只求职烘焙师岗位」，不考虑本岗。"}
```

`reason` **整句含编号和标点 ≤40 字**，格式 `H编号：…「原文短引」…` 或 `OFF：…「原文短引」…`。例如已确认 H1 必须本科时，可写 `H1：「最高学历为大专」，低于本科门槛。` 短引 ≤30 字，须能证明该人明确违背此项或明确不考虑本岗。只看到“大专”但另有本科、证书计划考试而非取得、履历没写、当前做其他工作等，不能据此淘汰。有歧义用完整待定档。不得仅给一句无法追溯的结论。

`score:null` 表示**未逐维评分**，不是 0 分。导出器保留决定性引句供复核，维度/亮点/风险不虚构；未展开的基础字段也不声称“简历未提及”。报告显示分数“—”，Excel 显示“未评分”，排在数值分之后。异常件不是不匹配，不填评估 JSONL。
